## 修复的问题

### 1. ✅ 调度器启动失败

**问题描述**:
- Home 页面点击"启动调度器"后，提示等待3-5秒刷新，但刷新后调度器仍显示未启动

**根本原因**:
- 使用 `python` 命令而非 `sys.executable`，可能调用错误的 Python 解释器
- 后台进程未正确分离，导致进程启动失败
- 缺少日志文件重定向，导致输出丢失

**修复方案**:
```python
# 修复前
subprocess.Popen(
    ["python", "-m", "m7_scheduler.cli", "start", "--background"],
    cwd=str(ROOT),
)

# 修复后
log_file = ROOT / "data" / "logs" / "scheduler.log"
log_file.parent.mkdir(parents=True, exist_ok=True)

subprocess.Popen(
    [sys.executable, "-m", "m7_scheduler.cli", "start", "--background"],
    cwd=str(ROOT),
    stdout=open(log_file, "a", encoding="utf-8"),
    stderr=subprocess.STDOUT,
    creationflags=0x00000008 if sys.platform == "win32" else 0,  # DETACHED_PROCESS
)
```

**影响文件**:
- `dashboard_v2/Home.py` (启动调度器、重启调度器、停止调度器)

### 2. ✅ Unicode 编码错误 (GBK codec)

**问题描述**:
- 手动触发任务时报错：`UnicodeEncodeError: 'gbk' codec can't encode character '▶'`
- 影响所有通过 CLI 触发的任务（M12扫描、信号处理等）

**根本原因**:
- Windows 控制台默认使用 GBK 编码
- Rich 库输出的 Unicode 字符（如 ▶）无法被 GBK 编码
- `Console()` 默认配置未禁用 legacy Windows 模式

**修复方案**:
```python
# 修复前
console = Console()

# 修复后
console = Console(force_terminal=True, legacy_windows=False)

# 同时将特殊字符替换为 ASCII 安全字符
console.print(f"[cyan]> 触发任务: {task_name}[/cyan]")  # 使用 > 替代 ▶
```

**影响文件**:
- `m7_scheduler/cli.py` (line 38, line 173)

### 3. ✅ 持仓页面 KeyError

**问题描述**:
- 持仓页面显示报错：`KeyError: 'cost_basis'`
- 错误发生在计算市值时

**根本原因**:
- 使用 `df_positions.get("cost_basis")` 尝试从 DataFrame 获取列
- DataFrame 的 `.get()` 方法用于获取列对象，不是字典的 `.get()`
- 当 `current_price` 列不存在时，代码逻辑错误

**修复方案**:
```python
# 修复前
df_positions["市值"] = df_positions["quantity"] * df_positions.get("current_price", df_positions["cost_basis"])

# 修复后
if "current_price" not in df_positions.columns:
    df_positions["current_price"] = df_positions.get("cost_basis", 0)

df_positions["current_price"] = df_positions["current_price"].fillna(df_positions["cost_basis"])
df_positions["市值"] = df_positions["quantity"] * df_positions["current_price"]
```

**影响文件**:
- `dashboard_v2/pages/1_💼_持仓.py` (line 85-88)

### 5. ✅ 所有页面的 subprocess 调用

**问题描述**:
- 所有页面使用 `python` 命令调用 CLI，可能调用错误的解释器

**修复方案**:
- 统一替换为 `sys.executable`

**影响文件**:
- `dashboard_v2/Home.py` (M12扫描、信号处理、调度器控制)
- `dashboard_v2/pages/4_🧠_情绪面.py` (立即采集)
- `dashboard_v2/pages/5_⚙️_调度器.py` (手动触发任务)

**修复示例**:
```python
# 修复前
subprocess.run(["python", "-m", "m7_scheduler.cli", "run", task_name], ...)

# 修复后
subprocess.run([sys.executable, "-m", "m7_scheduler.cli", "run", task_name], ...)
```

## 预防措施

### 1. 代码规范

**使用 sys.executable 而非硬编码 python**:
```python
import sys
subprocess.run([sys.executable, "-m", "module.name"], ...)
```

**DataFrame 列访问**:
```python
# 检查列是否存在
if "column_name" not in df.columns:
    df["column_name"] = default_value

# 使用 fillna 处理缺失值
df["column"] = df["column"].fillna(default_value)
```

**Rich Console 配置**:
```python
# Windows 环境下禁用 legacy 模式
console = Console(force_terminal=True, legacy_windows=False)
```

### 2. 依赖管理

创建 `dashboard_v2/requirements.txt`:
```txt
streamlit>=1.28.0
plotly>=5.18.0
pandas>=2.1.0
```

安装依赖：
```bash
pip install -r dashboard_v2/requirements.txt
```
