### 2.2 核心算法评估

#### 异动检测算法
- **实现文件**: `m12_opportunity_catcher/anomaly_detector.py`
- **算法**: 基于价格变化率、成交量变化率、振幅等指标
- **阈值**: 
  - 涨跌幅 > 3%
  - 成交量放大 > 2倍
  - 振幅 > 5%
- **评估**: ✅ 算法合理，但阈值可能需要根据市场调整

#### 反向溯源流程
- **实现文件**: `m12_opportunity_catcher/retro_engine.py`
- **流程**: 异动检测 → 信号匹配 → 趋势判断 → 机会生成
- **评估**: ✅ 流程完整，但信号匹配逻辑可能需要优化

#### 趋势阶段判断
- **实现文件**: `m12_opportunity_catcher/trend_classifier.py`
- **阶段**: 启动期、加速期、高潮期、衰退期
- **评估**: ✅ 分类合理，但可能需要更多历史数据验证

### 2.3 发现的问题

#### 🔴 P0 问题（阻塞性）
1. **扫描耗时过长（30+分钟）**
   - 影响: 10分钟间隔无法满足，可能触发 futu API 超时
   - 原因: 全景扫描标的数量过多（A股4998只、港股1356只、美股1819只）
   - 修复: 
     - 方案1: 缩小扫描范围（只扫描流动性好的标的）
     - 方案2: 并行化扫描（多线程/多进程）
     - 方案3: 增量扫描（只扫描有变化的标的）

#### 🟡 P1 问题（重要但不阻塞）
1. **盘前/盘后扫描逻辑简化**
   - 影响: 未充分利用盘前/盘后时间窗口
   - 建议: 
     - 盘前: 集成隔夜新闻、情绪面分析、外盘影响
     - 盘后: 全量扫描、异动排序、扩展监控池

2. **监控池未持久化**
   - 影响: 无法跟踪长期关注的标的
   - 建议: 创建 `data/watchlist.json` 持久化监控池

3. **历史案例库未充分利用**
   - 影响: 无法基于历史案例优化策略
   - 建议: 定期分析历史案例，提取成功模式

#### 🟢 P2 问题（优化项）
1. **缺少 Dashboard 展示**
   - 影响: 无法可视化查看扫描结果
   - 建议: 在 Streamlit Dashboard 中添加 M12 页面

2. **缺少飞书通知**
   - 影响: 发现机会时无法及时通知
   - 建议: 集成飞书机器人，发送机会通知

3. **异动检测阈值固定**
   - 影响: 无法适应不同市场环境
   - 建议: 根据市场波动率动态调整阈值
