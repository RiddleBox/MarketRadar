### 1.2 关键缺失模块

#### ❌ **M13 信号输出接口**（P0 - 紧急）
**功能描述**: 标准化交易信号输出接口  
**当前状态**: 不存在  
**影响**: M12 生成机会后，无法输出标准化交易信号给下游系统（QMT/富途）  
**建议实现**:
```python
class TradingSignal:
    symbol: str          # 股票代码
    direction: str       # LONG/SHORT
    size: float          # 仓位（%）
    entry_price: float   # 入场价
    stop_loss: float     # 止损价
    take_profit: float   # 止盈价
    reason: str          # 信号原因
    confidence: float    # 置信度
    time_horizon: str    # 时间窗口
```

#### ❌ **M14 实盘对接层**（P0 - 紧急）
**功能描述**: 与券商API（QMT/富途）对接  
**当前状态**: 不存在  
**影响**: 无法将机会转化为实盘交易  
**建议实现**:
- QMT API 适配器
- 富途 API 适配器
- 统一交易接口（下单/撤单/查询）

#### ❌ **M15 风控模块**（P0 - 紧急）

**影响**: 缺少组合层风控、熔断机制、风险预算  
**建议实现**:
- 单笔最大仓位限制
- 总持仓限制
- 单日最大交易次数
- 连续亏损熔断
- 风险预算管理

#### ❌ **M16 监控告警**（P1 - 重要）

## 二、架构合理性评估

### 2.1 架构优势 ✅

1. **模块化设计**: M0-M12 职责清晰，易于扩展
2. **推理引擎**: 因果链推理 + 历史案例检索，核心竞争力
3. **持久化**: M9 持仓持久化（SQLite）已完成
4. **去重机制**: M0 消息去重已完成
5. **双轨协同**: 主动信号 + 异动信号协同已完成
6. **测试覆盖**: 253+ tests passed，质量保障

### 2.2 架构缺陷 ⚠️

#### 1. **M3 推理引擎缺少评分化**（P0）
**问题**: 当前推理引擎输出"是/否"判断，缺少置信度评分  
**影响**: 无法区分高置信度机会和低置信度机会  
**建议**: 引入 `confidence_score`（0-1），基于：
- 因果模式匹配度
- 历史案例相似度
- 信号强度
- 时间窗口准确性

#### 2. **M4 行动设计缺少参数化**（P1）
**问题**: 止损/止盈/仓位建议硬编码在代码中  
**影响**: 无法灵活调整策略参数  
**建议**: 外置参数配置文件，支持：
- 不同品类（ETF/股票/期货）的参数模板
- 不同风险偏好的参数集
- A/B 测试不同参数组合

#### 3. **M5 持仓管理缺少生命周期管理**（P0）
**问题**: 当前只有基础持仓跟踪，缺少失效条件监控  
**影响**: 持仓可能在失效条件触发后仍然持有  
**建议**: 实现持仓状态机：
- OPEN → MONITORING → INVALIDATED → CLOSED
- 监控失效条件（时间窗口过期、前提条件变化）

#### 4. **M7 调度器缺少状态持久化**（P1）
**问题**: 重启后丢失 `last_run` 状态  
**影响**: 可能导致任务重复执行或遗漏  
**建议**: 实现 `scheduler_state.json` 持久化

#### 5. **数据源缺少降级策略**（P1）
**问题**: AKShare/YFinance 故障时系统停止工作  
**影响**: 单点故障风险  
**建议**: 实现数据源降级：
- AKShare → YFinance → 历史数据
- 实时行情 → 延迟行情 → 日线数据
