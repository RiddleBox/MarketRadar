```python
# m12_opportunity_catcher/anomaly_detector.py:217-266
def _check_intraday(instrument, market, price_feed):
    snap = price_feed.get_price(instrument)  # 获取实时价格
    if snap is None or snap.price <= 0:
        return None  # 无数据则跳过
    
    current_price = snap.price
    prev_close = snap.prev_close
    
    if prev_close is None or prev_close <= 0:
        return None  # 无昨收价则跳过
    
    change_pct = (current_price - prev_close) / prev_close * 100
    
    if abs(change_pct) < min_change_pct:
        return None  # 涨幅不足5%则跳过
```

**结论**: 扫描逻辑依赖实时价格数据。

## 三、根因分析

### 核心发现

**M12扫描0异动是【正常现象】，非逻辑疏忽。**

### 原因链

```
休市时段触发扫描
  ↓
price_feed.get_price() 无法获取实时价格
  ↓
返回 None 或过期数据（prev_close为空）
  ↓
_check_intraday() 返回 None（跳过该股票）
  ↓
遍历8052只股票，全部返回None
  ↓
anomalies = [] （空列表）
  ↓
run_intraday_scan() 返回 []
  ↓
m12_scan_results.json 记录 total_opportunities=0
```

### 时间规律验证

| 扫描时间 | 市场状态 | 实时价格可用性 | 扫描结果 |
|---------|---------|--------------|---------|
| 11:17-17:03 | 交易时段 | ✅ 可用 | 2-3个异动 |
| 23:36起 | 休市时段 | ❌ 不可用 | 0个异动 |

**结论**: 扫描结果与市场开闭市状态完全相关。

## 六、诊断结论

### 主结论

**M12扫描0异动是【正常现象】，非逻辑疏忽。**

### 原因

1. **设计正确**: 盘中扫描依赖实时价格是合理的
2. **数据缺失**: 休市时段无实时价格数据
3. **调度不当**: 调度器在休市时段仍然触发扫描

### 影响评估

✅ **不影响功能**:
- 交易时段扫描正常工作（4月28日成功发现14个异动）
- 空列表是合法输出，不会导致错误

⚠️ **影响效率**:
- 33次无效扫描浪费计算资源
- m12_scan_results.json 充斥无意义的0记录
- 日志噪音增加

---

## 七、建议（不修改逻辑）

### 1. 调度器时间优化（建议）

**目标**: 仅在交易时段触发M12扫描

**方法**: 
- 为M12任务添加 `active_hours` 配置
- 或在任务函数开头检查市场状态，休市时直接返回

### 2. 数据记录优化（建议）

**目标**: 减少无意义的0记录

**方法**:
- 仅在发现异动时记录到 `m12_scan_results.json`
- 或添加 `market_status` 字段区分"休市0异动"和"交易时段0异动"

### 3. Dashboard展示优化（建议）

**目标**: 向用户解释0异动的原因

**方法**:
- 在Tab5中显示"最近扫描: 0个异动（休市时段）"
- 过滤掉休市时段的扫描记录
