## 三、正确的架构理解

### signal_pipeline 和 M12 的分工

**signal_pipeline**（深度分析轨道）:
```
职责: 完整的显式+隐式信号处理链
频率: 每30分钟
流程: 
  1. 读取 data/incoming/（M0采集的结果）
  2. M1解码（显式信号）
  3. M2存储
  4. 查询历史信号（90天）
  5. M3判断（传入历史信号，触发隐式推理）
  6. M4行动设计
  
特点:
  ✅ 支持隐式推理（通过历史信号上下文）
  ✅ 生成完整的交易计划（M4）
  ✅ 处理所有类型的信号（财经+非财经）
```

**M12 盘前/盘中扫描**（快速响应轨道）:
```
职责: 快速机会发现（仅显式信号）
频率: 每10分钟
流程:
  1. M0采集（盘前）或 价格异动检测（盘中）
  2. M1解码（显式信号）
  3. M2存储
  4. M3判断（不传入历史信号）
  
特点:
  ❌ 不支持隐式推理（无历史信号上下文）
  ❌ 不生成交易计划（只生成机会对象）
  ✅ 快速响应（10分钟）
  ✅ 专注于时效性
```

### 为什么需要两条轨道？

**轨道1: signal_pipeline**（深度分析）
- 目标: 发现隐藏机会（二阶/三阶信息）
- 示例: "中沙签署新能源合作" → 推理出光伏产业链受益
- 需要: 历史信号、产业链图谱、因果推理
- 时效: 30分钟（需要深度计算）

**轨道2: M12 扫描**（快速响应）
- 目标: 快速捕获显式机会
- 示例: "某公司业绩预增" → 直接生成机会
- 需要: 实时数据、快速判断
- 时效: 10分钟（追求速度）

**两者互补，不冲突**：
- signal_pipeline: 慢但深（发现别人看不到的机会）
- M12: 快但浅（抢时间窗口）

## 五、正确的解决方案

### 问题重新定义

**真正的问题不是职责过重，而是**:
1. ❌ signal_pipeline 无时间窗口限制（全天运行，包括休市）
2. ❌ signal_pipeline 间隔过长（30分钟，盘中响应慢）
3. ❌ M12 和 signal_pipeline 缺乏协同（各自为政）

### 正确的优化方案

**方案A: 优化 signal_pipeline 配置（推荐）**

```python
# 修改 scheduler.py:226-232
self.register(ScheduledTask(
    name="signal_pipeline",
    fn=self._task_signal_pipeline,
    description="完整信号处理链（显式+隐式推理）→M1→M2→M3→M4",
    time_window=("09:00", "22:00"),  # ✅ 添加时间窗口（交易日+盘后）
    interval_minutes=15,              # ✅ 缩短间隔（30→15分钟）
    run_at_start=True,
))
```

**优点**:
- ✅ 保留完整的显式+隐式推理能力
- ✅ 提高盘中响应速度（15分钟）
- ✅ 节省资源（休市时不运行）
- ✅ 无需新增代码

**方案B: 保持现状，明确分工**

```
signal_pipeline（深度分析）:
  - 频率: 30分钟
  - 职责: 显式+隐式推理 + M4行动设计
  - 时间窗口: 添加限制（09:00-22:00）

M12 扫描（快速响应）:
  - 频率: 10分钟
  - 职责: 快速机会发现（仅显式信号）
  - 时间窗口: 已有限制（交易时段）

两者互补:
  - M12: 快速捕获显式机会（10分钟）
  - signal_pipeline: 深度挖掘隐式机会（30分钟）
```

**优点**:
- ✅ 保留两条轨道的优势
- ✅ 快速响应 + 深度分析
- ✅ 只需添加时间窗口配置
