# M13 深度调研 — 第一性原理

> **模块**: M13 Research Agent（深度调研代理）
> **创建**: 2026-05-07
> **一句话定位**: 信息补全是决策基础 — 当发现潜在机会时，主动搜索验证信息，用多维数据提升判断质量。

---

## 存在意义

现有管线存在**信息不对称**问题：

**M1轨道（新闻驱动）**：
- M1.5推理："降息利好银行股" → 但该银行基本面如何？是否有隐藏风险？
- 只基于单条新闻推理，缺乏多维验证

**M12轨道（价格驱动）**：
- 发现异动：某股票+5% → 反向溯源找到2条新闻 → 但置信度只有0.4
- 信息不足导致错失机会或误判风险

**M3判断**：
- 基于已有信号判断机会 → 但可能遗漏关键信息（如最新研报、财报预警）
- 判断质量受限于输入信息的完整性

M13的存在意义是：**主动补全信息，提升决策质量**。

不是被动等待信息流入，而是在关键决策点**主动搜索**：
1. 该标的的研报怎么说？
2. 最新财报数据如何？
3. 是否有反向证据？
4. 行业趋势是否支持？

---

## 核心约束（永远不能违反）

1. **信息必须可验证** — 所有调研结果必须有明确来源（研报/财报/新闻），不能凭空推测。

2. **调研不替代判断** — M13只负责信息收集和初步分析，最终判断仍由M3/M12/M4做出。

3. **成本意识** — 调研需要时间和API调用，只在关键决策点触发，不是每个信号都调研。

4. **时效性优先** — 调研结果必须在决策窗口内返回，超时则降级为"信息不足"而非阻塞流程。

5. **置信度透明** — 调研结果必须包含置信度评估，让下游模块知道信息质量。

6. **反向证据优先** — 主动寻找可能的利空因素，避免确认偏误。

7. **多源交叉验证** — 单一来源的信息不可靠，必须多源印证。

8. **结构化输出** — 调研结果必须结构化，便于LLM和人类理解。

9. **缓存机制** — 同一标的短期内不重复调研，避免资源浪费。

10. **失败容错** — 单个数据源失败不影响整体调研，降级返回部分结果。

| 职责 | 归属模块 | 原因 |

## 数据流

```
触发点1: M1.5推理后
  M1.5推理 → "平安银行可能受益于降息"（置信度0.6）
    ↓
  M13调研 → 搜索研报+财报+新闻
    ↓
  M13分析 → "零售转型顺利，但净息差承压"
    ↓
  M13输出 → 置信度调整至0.75 + 调研摘要
    ↓
  进入M2存储（带调研背景）

触发点2: M12反向溯源后
  M12异动 → 平安银行+5.2%
    ↓
  M12溯源 → 找到2条新闻（置信度0.4）
    ↓
  M13调研 → 搜索研报+财报+相关新闻
    ↓
  M13分析 → "业绩预告超预期，机构上调评级"
    ↓
  M13输出 → 置信度提升至0.75 + 调研摘要
    ↓
  M12趋势判断（基于更完整信息）

触发点3: M3判断后
  M3判断 → 生成机会（置信度0.65）
    ↓
  M13调研 → 最终验证（研报+财报+行业趋势）
    ↓
  M13分析 → "基本面支撑，但估值偏高"
    ↓
  M13输出 → 置信度调整至0.55 + 风险提示
    ↓
  M4行动设计（基于调整后的置信度）
```

## 触发策略

### 何时触发调研

**M1轨道**：
- M1.5推理置信度 > 0.5 → 触发调研验证
- 目的：过滤错误推理，发现反向因素

**M12轨道**：
- 反向溯源置信度 < 0.7 → 触发调研补充
- 目的：补充信息，提升置信度

**M3判断**：
- 生成机会置信度 > 0.5 → 触发最终验证
- 目的：最后一道防线，确保决策质量

### 何时不触发

- 置信度极低（< 0.3）→ 直接放弃，不浪费调研资源
- 置信度极高（> 0.9）→ 信息已充分，无需调研
- 同一标的24小时内已调研 → 使用缓存结果
- 调研队列已满 → 降级跳过

## 调研深度分级

### Level 1: 快速验证（< 30秒）
- 搜索最近5篇研报标题
- 查询最新财报关键指标
- 适用场景：M1.5推理验证

### Level 2: 标准调研（1-2分钟）
- 搜索最近10篇研报 + 摘要
- 查询财报详细数据
- 搜索最近20条相关新闻
- 适用场景：M12反向溯源补充

### Level 3: 深度调研（3-5分钟）
- 搜索最近20篇研报 + 完整内容
- 查询多期财报对比
- 语义搜索行业趋势
- 搜索产业链上下游信息
- 适用场景：M3最终验证

## 输出格式

```python
@dataclass
class ResearchReport:
    """调研报告"""
    symbol: str                          # 股票代码
    research_level: str                  # 调研深度: quick/standard/deep
    triggered_by: str                    # 触发来源: m1_5/m12/m3
    
    # 原始数据
    reports: List[Dict]                  # 研报列表
    news: List[Dict]                     # 新闻列表
    fundamentals: Dict                   # 基本面数据
    quote: Dict                          # 行情数据
    
    # LLM分析结果
    summary: str                         # 调研摘要（200字内）
    key_findings: List[str]              # 关键发现（3-5条）
    risk_factors: List[str]              # 风险因素（2-3条）
    confidence_assessment: str           # 置信度评估说明
    
    # 置信度调整
    confidence_multiplier: float         # 置信度乘数（0.5-2.0）
    confidence_delta: float              # 置信度增量（-0.3 ~ +0.3）
    has_major_negative: bool             # 是否发现重大利空
    
    # 元数据
    research_time: datetime              # 调研时间
    data_sources: List[str]              # 数据来源
    cache_hit: bool                      # 是否命中缓存
```

## 关键词

- **定向搜索 (Targeted Search)**: 按股票代码精确搜索
- **语义搜索 (Semantic Search)**: 基于主题的NL搜索
- **多源验证 (Multi-source Verification)**: 交叉验证信息真实性
- **反向证据 (Counter Evidence)**: 主动寻找利空因素
- **置信度调整 (Confidence Adjustment)**: 基于调研结果调整判断置信度
- **信息补全 (Information Completion)**: 填补决策信息缺口
