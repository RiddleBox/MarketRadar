# M17 Ten-Bagger Research — 第一性原理

> 模块代号: M17
> 模块名称: Ten-Bagger Research
> 创建日期: 2026-06-06
> 定位: 离线研究模块，用历史样本研究 90 自然日 10 倍股的上涨过程、可复制机制和延续性信号。

---

## 一句话定位

M17 不是实时机会捕捉模块，而是 MarketRadar 的离线研究模块。

它的核心任务是:

```text
先找全样本，再提取事实特征，最后归纳规则和模型。
```

研究主线固定为三步:

```text
Step 1: 样本收集
Step 2: 特征提取
Step 3: 规则/模型建立
```

---

## 研究目标

M17 要回答的问题不是:

```text
历史上有哪些妖股?
起涨点在哪里?
媒体说它为什么涨?
```

M17 要回答的是:

```text
历史上所有 90 自然日内上涨超过 1000% 的股票，
它们在上涨过程中表现出了哪些共同特征?

哪些上涨机制具有可复制性?

当股票已经上涨 100% / 200% / 300% 后，
如何判断它仍可能继续上涨至 1000% 以上?
```

最终目标不是解释过去的故事，而是建立一个可以反哺未来机会判断的机制框架。

---

## 核心原则

### 1. 样本先于解释

禁止先定义样本类型。

在样本收集阶段，不允许预设:

```text
Meme Stock
FDA Stock
AI Stock
Short Squeeze
SPAC
Crypto
EV
```

这些只能在完成样本和事实特征后，由数据和 Case File 归纳产生。

### 2. 事实先于分类

M17 可以记录事件事实，例如 FDA、临床试验、并购、破产、AI、Crypto、EV、IPO、SPAC、财报、监管审批等。

但记录事实不等于提前分类。

```text
事件字段是 observation。
机制类别是 conclusion。
```

### 3. 研究上涨过程，而不是只研究上涨前

M17 的重点不是寻找起涨点，而是研究上涨已经发生后的延续机制。

对于每个样本，必须研究:

```text
Day 0
Day 10
Day 20
...
Day 90
```

以及完整日频路径中的价格、成交量、波动率、回撤、市值、空头数据和市场结构变化。

### 4. 区分表面原因、资金原因、结构原因

每个 Case File 后续必须拆成三层:

```text
Layer 1: 表面原因
Layer 2: 资金原因
Layer 3: 结构原因
```

例如:

```text
AI / FDA / 重组                    -> Layer 1
Short squeeze / gamma squeeze      -> Layer 2
Small float / low liquidity         -> Layer 3
```

### 5. 不直接相信媒体叙事

媒体叙事只能作为待验证事实来源，不能直接作为机制结论。

每个解释都要继续追问:

```text
资金为什么持续买入?
市场结构为什么允许价格继续上涨?
这个机制是否在多个样本中重复出现?
```

### 6. 必须处理幸存者偏差

POC 阶段可以使用低成本数据源跑通流程，但正式研究结论必须明确处理或标注 survivorship bias。

低成本 POC 数据适合验证:

```text
样本扫描逻辑
90 自然日窗口计算
episode 合并
路径构建
Case File 模板
```

但 POC 数据通常不能覆盖完整退市、破产、改名、并股和异常交易标的，因此不能直接作为最终概率结论。

### 7. 研究结论必须可追溯

所有样本、事件、市场结构和结论都必须保留来源信息。

后续 Case File 至少要记录:

```text
source_url
source_name
published_at
retrieved_at
confidence
notes
```

### 8. M17 不直接参与交易

M17 不生成实时机会，不做仓位决策，不接实盘。

M17 的研究成果未来可以反哺:

```text
M12 价格异动和趋势阶段判断
M13 调研和证据补全
M3 机会判断
```

但在研究阶段，M17 必须与实时交易链路隔离。

### 9. 进度必须写回文档

M17 后续每推进一个步骤，都必须更新 `PROGRESS.md`。

任何重要口径变化、数据源变化、字段变化和结论变化，都必须在文档中留下记录。

## 已确认决策

截至 2026-06-06，已确认:

```text
1. 模块编号使用 M17。
2. 第一版样本范围先做美股。
3. 架构要支持后续扩展到 OTC、港股、A股、韩国市场等。
4. POC 阶段允许使用低成本数据源，但结果标记为 preliminary。
5. 90 天指 90 个自然日。
6. 使用自然日窗口内的收盘价计算涨幅。
7. 如果 end_date 不是交易日，使用 end_date 之后第一个交易日收盘价。
8. 研究阶段按照 样本收集 -> 特征提取 -> 规则/模型建立 推进。
9. 价格使用 raw close 和 adjusted close 双轨记录。
10. POC 阶段 yfinance 和 Stooq 并行，互相交叉验证。
11. Futu OpenD 和 Tushare Pro 可作为候选补充数据源。
12. 同一 ticker 的 qualifying windows 如果 start_date 间隔 < 90 自然日，则合并为同一 episode。
13. 100% / 200% / 300% 对照组留到 Step 3，在完整样本和特征基础上按模型需求构建。
```
